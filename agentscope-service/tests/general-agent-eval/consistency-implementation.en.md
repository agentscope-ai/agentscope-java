## Deployment and operation

Reuse the overlays for later upgrades.

[prepare_java_layers.py](prepare_java_layers.py) verifies Spring Boot entrypoints and main classes, selecting Tool Worker's executable classifier. Publication preserves the existing verified base image OS, architecture and runtime configuration, overlays verified artifacts and records the final registry digest. The final three Harness images are flattened so historical JAR layers do not distort cold startup. Other shared Java components use verified incremental layers on pinned bases, with identical component digests across all three namespaces. The release manifest records the actual method. Credentials are never added to layers.

The local machine controls publication, preflight, resource snapshots and Kubernetes fault injection. Environment/results use a 40Gi PVC; the temporary Rust builder uses 8 CPU/16Gi and an 80Gi cache PVC. Platform credentials are mounted only in the Runner; services receive only evaluation transport keys. Select native gateway policy with `--evaluation-profile` and use the same profile for deployment, preflight and Runner.

## Recovery rules

Failures preserve the exclusive lease and request evidence. Verify Session/Turn terminal state, tool tasks and pending gateway requests before closing the case and releasing the same owner's lease. Do not remove databases, steal locks, select the best retry or modify scoring. Safely verified fixes use a new batch while retaining original attempts.

The acceptance Runner now handles cancellation races explicitly: a 409 is accepted only after the exact Turn is confirmed terminal, recorded as `already_terminal`. Running conflicts and transport errors remain failures. This adds no model request, tool retry or budget allowance.
