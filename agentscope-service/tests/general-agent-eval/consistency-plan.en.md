# Managed Agents evaluation consistency plan

Date: 2026-10-31. Scope: AgentScope, pi and codex Managed Agents in Hangzhou.

This plan preserves the original gaps and objectives from the code inspection, deployment audit and smoke acceptance performed on 2026-10-30. Feasible changes were implemented and deployed to Hangzhou on 2026-11-01; see the current [implementation and acceptance record](consistency-implementation.en.md). The earlier model-alignment results remain in the [original acceptance record](reports/hangzhou-qwen38-20261030.en.md). Recheck live deployments before each evaluation batch.

## Objective and priorities

Compare task completion under the same tasks, model and external budgets. Align evaluation inputs, available capabilities and resource boundaries while retaining and recording native planning, context management and recovery behavior.

Priorities reflect impact on success, business state and comparability, rather than implementation effort. P0 gates expanded formal evaluation; P1 gates long-task and multi-turn evaluation; P2 gates concurrency, performance and cost comparisons. Follow table order within a priority. Existing single-task results remain smoke acceptance, not an overall ranking.

## Implementation boundaries and sequence

Add a public evaluation profile separate from the existing [model profile](../../deploy/profiles/qwen38-eval.json). The former covers datasets, case budgets, tools, recovery, sampling and deployment constraints; the latter covers model requests. Field names and values remain implementation decisions, not claims about existing APIs.

Define case/Session/Turn scope explicitly. Multiple Turns and future child Sessions share their case budget. Register model attempts before dispatch and settle token usage afterward. Unknown usage after interrupted streams must stay marked unknown and follow a predefined conservative budgeting rule, rather than becoming zero. Start the case clock at a common Runner admission point and report queuing separately.

Runner owns case lifecycle, orchestration and scoring; Agent Service / Session Service own durable admission and common budgets; Harness Runtime owns mappings and native behavior; Tool Worker owns tool execution and side-effect result handoff. Do not reimplement all three reasoning loops in the Runner.

1. **Shared conditions:** complete P0 and request/fault-injection checks; rerun a small identical short-task set as a new cohort, retaining old results.
2. **Long tasks and native behavior:** complete P1, define baseline/native modes, add long histories/results and multi-turn cases, then freeze formal tasks and repetitions.
3. **Scale and regressions:** complete P2, equalize performance resources and automate preflight/reporting. Configuration snapshots and usage collection can start in the first stage.

Do not replace native planning or force a shared summarizer. Disclose disabled baseline capabilities; record missing native features instead of masking them with undeclared external capabilities.
