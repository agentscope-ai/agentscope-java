模块由两个并列子包构成，依赖方向单向：`formatter` → `message`。
- `message` 子包以 `Msg` 为根，使用 Jackson `@JsonTypeInfo(property="role")` + `@JsonSubTypes` 实现基于 JSON 字段 `role` 的运行时多态，子类包括 `UserMessage`、`AssistantMessage`、`SystemMessage`、`ToolResultMessage`；内容体采用 Java 17 `sealed class ContentBlock permits ...` 配合 `type` 字段进行反序列化，具体块类型有 `TextBlock`、`ThinkingBlock`、`ImageBlock`、`AudioBlock`、`VideoBlock`、`ToolUseBlock`、`ToolResultBlock`、`HintBlock`、`DataBlock`，并通过 `Base64Source` / `URLSource` 抽象媒体来源；`MsgRole` 枚举限定角色集合，`GenerateReason`、`ToolCallState`、`ToolResultState`、`MessageMetadataKeys` 提供结构化元数据键常量；`Msg` 在构造时通过 `validateRoleContent` 按角色校验允许的 ContentBlock 子集（USER 允许 text/data/image/audio/video，SYSTEM 仅 text）。
- `formatter` 子包以泛型接口 `Formatter<TReq,TResp,TParams>` 定义三方 SDK 适配契约（`format`/`parseResponse`/`applyOptions`/`applyTools`/`applyToolChoice`），由 `AbstractBaseFormatter` 提供通用能力：文本提取时过滤 `ThinkingBlock`、多模态检测、工具结果转字符串、Base64 临时文件落盘等，并借助 `TracerRegistry.get().callFormat(...)` 包裹 trace；`ResponseFormat` 与 `JsonSchema` 描述结构化输出约束，`MediaUtils` 辅助媒体处理。
- 扩展点：`AbstractBaseFormatter` 暴露 `doFormat` 抽象方法供具体 Provider 实现覆盖，同时提供 `saveBase64DataToTempFile`、`convertToolResultToString` 等受保护钩子。
