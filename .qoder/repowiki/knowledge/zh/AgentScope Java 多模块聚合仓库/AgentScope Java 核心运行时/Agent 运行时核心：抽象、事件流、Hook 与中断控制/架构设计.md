模块按职责划分为四个子包，围绕 `Agent`/`AgentBase` 这一核心抽象展开：
- `agent/`：顶层 `Agent` 接口组合了 `CallableAgent`（同步/结构化输出）、`StreamableAgent`（事件流）、`ObservableAgent`（只读观察）三种能力；`AgentBase` 作为所有具体 Agent 的基类，通过 `Mono.using` + `callGates` 实现 per-call 资源管理、按 key 的串行化门控（默认无、ReActAgent 按 `(userId,sessionId)` 序列化）、以及 `runLifecycle` 中 preCall → doCall → postCall 的统一钩子编排，并通过 `SubagentEventBus` 把子工具产生的旧式 `Event` 直接注入父级 sink。
- `event/`：以 `AgentEventEmitter` 为入口，将执行过程拆分为 `AgentStart/End/Result`、`ModelCallStart/End`、`TextBlock*`、`ThinkingBlock*`、`ToolCall*`、`ToolResult*`、`RequireUserConfirm`/`RequireExternalExecution` 等一组不可变事件类型，供 `streamEvents()` 下游消费；`SubagentExposedEvent` 用于子 agent 暴露给父级的元信息。
- `hook/`：提供已标记 `@Deprecated(forRemoval=true)` 的 `Hook` 单入口模型（`onEvent(HookEvent)` + `priority()`），由 `AgentBase` 在 `notifyPreCall`/`notifyPostCall`/`notifyError` 中以排序后的链表顺序依次 `flatMap(hook::onEvent)` 串联；配套 `PreCall/PostCall/PreReasoning/...` 等事件及 `LegacyHookDispatcher`、`JsonlTraceExporter` 等实现。
- `interruption/`：`InterruptControl` 是每会话原子信号（`AtomicBoolean` + `AtomicReference<Msg>` + `InterruptSource`），被挂载到对应 `AgentState` 的 slot 上，配合 `InterruptContext` 让 `AgentBase.handleInterrupt` 能区分来源并返回恢复消息。
依赖方向单向：`agent` 依赖 `hook` 和 `interruption`，`hook` 不反向依赖 `agent` 的具体实现，仅引用 `Agent` 接口与 `RuntimeContextAware` 标记；`event` 与 `agent` 之间通过 `AgentEventEmitter.fromContext(ContextView)` 解耦，避免工具代码直接持有 FluxSink。
