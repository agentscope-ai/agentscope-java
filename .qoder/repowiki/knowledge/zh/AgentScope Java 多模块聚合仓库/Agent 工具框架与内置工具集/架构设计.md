模块以 `io.agentscope.core.tool` 为根包，形成清晰的三层结构：
- 抽象层：`AgentTool` 接口 + `ToolBase` 抽象类（Builder 构造、`dangerousFiles/dangerousDirectories` 危险路径白名单、`checkPermissions`/`generateSuggestions` 权限钩子、`externalTool`/`stateInjected`/`mcp` 标记）+ `@Tool` / `@ToolParam` 注解，定义工具元数据与安全语义。
- 运行时基础设施：`Toolkit` 作为门面，组合 `ToolRegistry`（名称→工具映射）、`ToolGroupManager`（分组激活状态）、`MetaToolFactory`（动态启用/禁用组的 meta 工具）、`McpClientManager`（MCP 客户端生命周期）、`ToolSchemaProvider`/`ToolSchemaGenerator`（JSON Schema 生成），并通过内部 `ToolExecutor` 统一处理参数合并、schema 校验、并发分区（按 `concurrencySafe` 将连续 safe 工具用 `Flux.mergeSequential` 并行，unsafe 串行）、超时/重试/优雅关闭保护、`ToolSuspendException` 外部工具挂起流。
- 反射桥接：`ReflectiveFunctionTool` 把 `@Tool` 方法包装成 `ToolBase`，由 `ToolMethodInvoker` 完成参数转换与 `AgentState` 注入；`SchemaOnlyTool` 仅暴露 schema 供外部执行；`DefaultToolResultConverter`/`NoOpToolEmitter` 提供默认结果与流式回调实现。

四个子包是具体工具实现，均遵循同一契约：
- `builtin/TodoTools.java`：纯函数型 `@Tool` 示例。
- `coding/`：`ShellCommandTool` 通过 `CommandValidator` 策略（`UnixCommandValidator`/`WindowsCommandValidator`）做平台相关的安全校验，使用独立 daemon 线程池异步读取 stdout/stderr 避免管道死锁。
- `file/`：`ReadFileTool`/`WriteFileTool` 继承 `ToolBase`，复用 `isDangerousPath` 危险路径检测与权限建议。
- `mcp/`：`McpClientWrapper` 同步/异步封装 + `McpTool` 将远端 MCP 工具转为本地 `AgentTool`，由 `McpClientManager` 统一管理注册/注销。
- `subagent/`：`SubAgentTool` 把另一个 Agent 作为工具暴露，支持会话级状态持久化。

依赖方向单向向下：子包 → 根包抽象层，根包不反向依赖子包；`Toolkit` 是唯一对外入口。
