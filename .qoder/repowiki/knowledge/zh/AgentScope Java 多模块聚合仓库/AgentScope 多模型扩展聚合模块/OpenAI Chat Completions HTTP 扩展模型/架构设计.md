模块以 `OpenAIModelProvider`（注册于 `META-INF/services/io.agentscope.core.model.spi.ModelProvider`）作为入口，按 `openai:` 前缀匹配并构造 `OpenAIChatModel`。

内部分层清晰：
- `OpenAIChatModel` 继承 `ChatModelBase`，负责合并 `GenerateOptions`、选择流式/非流式路径、调用 `OpenAIClient`，并通过 `Formatter<OpenAIMessage, OpenAIResponse, OpenAIRequest>` 将 AgentScope 消息与 OpenAI JSON 互转；
- `OpenAIClient` 是无状态 HTTP 层，封装 OkHttpTransport 的同步 `call`、SSE 流式 `stream` 以及通用 `callApi`，统一处理 URL 拼接（自动剔除 base URL 中的 `/vN`）、鉴权头、错误码映射到 `OpenAIException` 子类型；
- `dto/` 包是纯 Jackson POJO，对应 OpenAI Chat Completions 请求/响应结构（含 `OpenAIMessage`、`OpenAIRequest`、`OpenAIResponse`、`OpenAIUsage`、工具/多模态字段等）；
- `formatter/` 包采用模板方法：`OpenAIBaseFormatter` 继承 `AbstractBaseFormatter` 提供公共的 `parseResponse`、`applyCacheControl`、`buildRequest` 等，具体提供商差异由 `OpenAIChatFormatter`、`DeepSeekFormatter`、`GLMFormatter` 及其 MultiAgent 变体覆写 `doFormat`、`applyOptions`、`applyTools`、`applyToolChoice`；
- `exception/` 包按 HTTP 语义细分 `AuthenticationException`、`RateLimitException`、`BadRequestException` 等，均由 `OpenAIException.create(statusCode, ...)` 工厂分发；
- `tool/OpenAIMultiModalTool` 暴露多模态工具能力；`credential/OpenAICredential` 承载密钥配置。

依赖方向单向：`OpenAIChatModel → OpenAIClient → HttpTransport`，Formatter 仅消费 DTO，DTO 不反向依赖业务类，便于独立测试。
