模块由三层构成：
- 接口层 `Model.java`：声明唯一调用入口 `stream(List<Msg>, List<ToolSchema>, GenerateOptions)` 返回 Reactor `Flux<ChatResponse>`，并以 default 方法暴露 `supportsNativeStructuredOutput()` / `supportsNativeStructuredOutputWithTools()` / `getContextWindowSize()` 等能力探测。
- 抽象基类层 `ChatModelBase.java`：实现 `stream` 作为模板方法，外层通过 `TracerRegistry.get().callModel(...)` 注入追踪，内部委托子类覆写的 `doStream(...)`；同时暴露 `setContextWindowSize`、`setNativeStructuredOutput`、`setNativeStructuredOutputWithTools` 供子类配置能力。
- 注册中心层 `ModelRegistry.java`：单例式静态注册表，维护三类来源——精确命名的 `namedModels`（ConcurrentHashMap）、按正则匹配的 `userFactories`（CopyOnWriteArrayList，新注册优先）、以及通过 `ServiceLoader<ModelProvider>` 从当前线程上下文 ClassLoader 和自身 ClassLoader 双路加载的 SPI 提供者列表。`resolve(modelId, context)` 严格按“命名 > 缓存 > 用户工厂(新→旧) > SPI provider”顺序查找，并使用 `ModelCacheKey` 对空上下文走 legacy 键、非空且显式启用缓存时走标准指纹或显式 cacheId 的三路策略，API Key 以 SHA-256 摘要写入指纹避免泄露。
依赖方向：`ChatModelBase` → `Model`；`ModelRegistry` → `Model` 及外部 `io.agentscope.core.model.spi.ModelProvider`；反向无依赖，保证扩展点解耦。
