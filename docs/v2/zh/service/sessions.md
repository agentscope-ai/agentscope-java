# 会话、任务与审批

Sessions 适合直接对话和观察运行历史；Tasks 与 Runs 帮助定位一次协作中的具体工作。

## 阅读一次执行

先找到原 Session 或 Issue，再检查对应任务和最新 Attempt。关注触发输入、实际执行的 Agent、Environment / Runtime、事件和最终结果。重试后仍要保留原失败记录用于排查。

流式回复依赖 SSE。浏览器断开后可以重新读取持久事件；反向代理需要允许长连接并及时转发数据。不要因为页面刷新就重复提交相同工作。

## 处理需要人工操作的状态

工具确认通常属于当前 Session；Issue 评审属于交付验收；资源申请属于权限授权。处理前先确认请求类型、请求人、资源和影响范围。

如果工具被拒绝，Agent 可能需要替代方案；如果缺少权限，需要资源所有者或管理员授予必要权限。仅重试不能修复这些条件。

## 排查停滞

依次检查：是否有未处理确认、模型请求是否失败、Environment / Host 是否在线、任务是否已派发、相关组件日志是否存在异常。保留 Session、Task、Attempt 和 Run ID，便于关联日志。
