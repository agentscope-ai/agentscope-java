# Issue 与 Team 协作

用 Issue 表达要完成的工作，用 Team 组织 leader 与成员，再用执行记录检查工作如何推进。

## 建立一个小型 Team

先分别验证每个 Agent 可以独立完成一次任务。创建 Team，选择 leader 和成员，写明成员职责，例如研究、实现和复核。按实际需要设置协作策略和人工评审要求。

创建一个目标明确的 Issue，例如“比较两个实现方案，给出推荐和验证步骤”，写清交付物与验收标准，再分配给 Team。

## 观察协作

从 Issue 讨论查看 leader 的判断、成员结果和交付物；从 Tasks / Runs 查看派发、尝试、失败和等待原因。需要补充条件时，在原 Issue 中提供信息，保留完整讨论上下文。

leader 的一轮回复结束不代表所有成员都结束。某次执行失败也不意味着要丢弃整个 Issue；先确认失败任务、尝试和阻塞原因，再选择重试或补充信息。

## 人工评审

若进入评审或审批状态，查看交付物后明确接受或提出修改意见。修改意见应描述缺口与可验证的完成条件。需要文件时保留 Artifact，避免只在会话中留下机器上的临时路径。

Team 适合动态协作；Workflow 适合预先定义步骤和依赖。两者可以配合，但 Run 节点状态与 Issue 的业务验收状态应分别查看。
