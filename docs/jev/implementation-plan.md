# 实施路线、工作项与验收

本计划按已确认的Harness优先顺序推进。所有新用途默认关闭，先SHADOW后按用途开启ENFORCE；不以离线fixture说明真实模型效果。

| H1 | 独立适用性、单候选、none、批次及原候选回退 | 业务金标与工具召回对照 |

| H3 | 调用内粘性、候选资格和能力复核、原模型回退 | 真实模型能力目录与成本对照 |

每块基本API及案例从[Harness入口](guides/harness-runtime.md)、[Service入口](guides/service-api.md)、[应用入口](guides/application-api.md)进入。高级能力目前是首个显式调用边界，不宣称完整自动改造已经交付。

下一步应选择真实应用接线与金标回放，再逐项扩展接管；未校准用途保持SHADOW。

## 分阶段交付顺序

以本次批准的 H0 → H1 → H2 → H3 → S1 → A1/A2/A3 为推进顺序。高级能力仅交付显式调用的建议 API，后续逐项接入实际运行链路。

1. 第一阶段：公共执行、工具选择、执行防护与模型路由；代码和离线案例已提供，真实模型校准待完成。
2. 第二阶段：Service 配置和事件已接入；客服、知识助手及有限修订具备应用 API，实际业务闭环仍需接线验收。
3. 第三阶段：监督、上下文、记忆、阶段团队路由和浏览器只读建议具备首个调用边界；自动化运行与持久化能力不在当前已完成范围。

下一块优先进行 S1 的实际运行验收与 A1 客服草稿接线：使用测试业务记录，验证配置隔离、确认参数变化、决策事件归属与关闭恢复；随后固定金标，在 SHADOW 下比较质量和耗时。

## 已实现入口与后续接线

Judge、工具none语义、执行预检、Service观察和应用组件已增量实现。后续优先将实际业务草稿/检索结果接入现有应用API，固定业务金标，并验证SHADOW与ENFORCE的端到端差异。

在当前模块内复用注入的`Function<SystemOneRequest, Mono<SystemOneResult>>`做离线fake，沿用JUnit/Reactor Test验证错误和取消。JevJudge的已实现API见对应使用文档；其余拟议能力不得写成现有API。

## 必须覆盖的组合测试

- Middleware顺序：较大order靠外、同order注册顺序、返回阶段顺序；onActing多调用。
- 权限：Jev允许但PermissionEngine拒绝、用户确认后参数变化、不可见候选不进state。
- 状态：同Agent不同user/session并发，当前调用状态读取，恢复后重算过期判断。
- 事件：拒绝项结果配对、允许项恰好执行一次、取消后不再派发。
- 故障：超时/重试总预算、429/529、非法响应、无置信度、后端切换重校准。
- 业务：退款条件反转、无检索证据、测试未运行、记忆冲突。

这些是计划中的行为测试，不由文档校验替代。新增行为按仓库要求添加单元测试；live集成测试独立显式启用。

## 各阶段退出条件

P0：客户端/策略/状态失败可区分，数据与成本可追踪。P1：至少一个业务闭环有金标、影子流量与回退证明。P2：对端到端任务有收益且无关键质量退化。P3：平台配置与运行版本一致，具备权限、预算、灰度及回滚记录。

产品代码PR提交前执行仓库要求的`mvn clean verify`；开发时先用目标模块测试定位问题。仅文档变更进行链接、MDX、样本结构及示例编译校验，不把这些写成生产功能已经验收。

## 决策待定

- 第二个后端出现后是否抽独立SPI，以及放置模块。
- 每个场景的阈值、延迟预算和人工复核容量。
- AgentScope Service当前资源/身份/评估API映射。
- 大候选集预检索与分块策略，业务召回是否可接受。
- 在线总预算和取消是否要下沉HttpTransport公共能力。

每项在实施时形成明确结论与证据，不使用未经验证的默认值填满配置。

## 本轮补齐的四项 Agent 集成

- 内容护栏：`JevGuardrail` 策略 + `JevResponseMiddleware`，已接入 Agent 模型调用及 Service content 配置。
- 最终草稿：同一响应中间件完成质量评审及无工具有限修订，Service quality 配置可启用。
- 检索：`JevKnowledge` 兼容现有 Knowledge，`JevKnowledgeTool` 接入 Toolkit；应用层 JevRag 保留。
- 评估：新增扩展级 Evaluator、JevEvaluator、固定样本 runner；当前仓库无可复用的统一 Core 评估 SPI。

[API 与可运行组合案例](guides/agent-integration-example.md)。这四项已从独立函数推进到可运行的框架适配，生产数据源、部署验收、真实金标对照仍待开展。下一块是 Service 测试环境的 content/quality SHADOW 验收和业务金标回放；暂不继续扩展高级建议 API。
