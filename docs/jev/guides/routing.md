# 工具适用性、模型与阶段路由

更新：本页保留调研与设计背景；当前已实现的API和限制见[增量实现使用指南](tool-selection-api.md)，不要将旧基线描述作为最新行为。

## 工具筛选现状

`JevToolSelectionMiddleware`默认OFF。启用后在onReasoning按独立Noul适用性筛选，默认通过阈值0.8、拒绝阈值0.2、maxTools=3；单候选也检查。明确none只保留必要工具，错误或不确定回退原输入；每64个候选分批，共享总预算。见[当前API](tool-selection-api.md)。

## 曾调研的可替代设计

借鉴spring-ai-typesafe的“两问法”：Choice问候选内最佳工具；独立Noul问是否有任何候选适用。两问共享state，包含当前目标、必要工具结果与已授权候选描述。

| 状态 | 处理 |
| --- | --- |
| 确认无适用工具 | 返回空的可选工具集合；保留必要终止/澄清能力 |
| 候选中有适用工具 | 返回topK，继续原模型规划 |
| 低确定性 | 保留经授权候选或澄清，按业务策略决定 |
| 服务失败 | 回原策略并记ERROR，不能伪装成none |

先粗召回再精排，避免把上千工具全送入模型；分块代表可能丢失同组第二个必要工具，需多工具任务评测。生成模型最终调用时再次执行权限和参数检查：不在本轮推荐列表不是严格拒绝边界。

## 模型路由现状与改造

现有`JevModelRouterMiddleware`在onAgent读取最新用户文本，选一次模型并放入RuntimeContext；onModelCall通过ModelCallInput替换模型，同一调用后续轮次不重新选择。默认OFF，confidenceThreshold=0.8，失败回原模型。该模式可直接作为入口路由实验基线。

已提供eligible与compatible谓词，任务类型、输入长度、工具/多模态/结构化输出能力由宿主目录判断，先由代码过滤模型池；Jev只在剩余候选中选择。保证回退模型能够满足原请求协议，不能切到不支持所需工具的模型。

阶段路由是后续能力：只在显式阶段边界更换，不因概率抖动每轮切换；计入缓存损失、路由费用、失败重试与质量下降。不要将当前“一次调用选一次”写成已实现的动态阶段路由。

## 服务故障与验收

路由失败通常回原模型；但原模型不可用时明确失败，禁止循环路由。路由决定写入调用上下文，不能保存在共享Middleware可变字段。并发Session应互不影响。

验收同时看必要工具Recall@K、无适用候选拒答、实际任务完成率和单位成功任务成本。对同义请求、候选顺序扰动、单候选、不完整参数、多工具依赖分别测试。短题路由省下的token可能抵不过额外网络往返。
