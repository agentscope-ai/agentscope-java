# 试点二：带证据的企业知识问答

## 固定场景

用户问“2026版差旅政策是否允许预订高级房型”。候选中有现行规则、已废止旧版、适用不同职级的例外、无关酒店介绍和嵌入伪指令的页面。使用[固定样本](../examples/scenarios.jsonl.txt)的knowledge-01。

普通问答服务和Agent知识工具都可使用：取授权候选后调用后处理器；生成与引用复核放应用层，不需要旧Knowledge接口。

## 输入合同

每个片段包含chunkId、sourceId、effectiveVersion、访问范围和正文。规则先剔除无权限内容，再按版本筛选；模型只看到允许的内容。问题定义要求区分“支持结论”“背景”“冲突”“不足”，而不只问相关性。

对每个独立片段用同一state问相关性、证据性和注入迹象；结果以chunkId对齐。首轮关闭自动丢弃，仅输出分组和排序，对照原召回结果。后续接管时保留可恢复的原候选与来源版本。

## 期望处理

- 现行标准政策进入主要证据。
- 旧版政策不能作为当前结论，保留版本原因供审计。
- 特定职级例外要求用户适用条件；信息不足则澄清。
- 页面伪指令不改变系统规则，进入隔离或复核区。
- 最终答案只引用真实返回的chunkId；缺少直接依据时明确不足。

## 验收和故障注入

以查询为独立单位建立带相关性与证据标签的数据集；同一文档的近重复片段不能跨开发/验收划分。覆盖混合版本、同名对象、冲突政策、无相关候选和服务失败。

对照三条链：原检索；原检索加Jev；原检索加生成式评审。记录端到端回答正确率、证据Recall@K、引用支持率、错删率、每查询费用与P95。单片段判断准确率提升不保证问答提升。

重排超时保留原检索次序并标记未评分；风险筛查超时的片段按应用策略隔离，不能和普通排序失败共用一个无条件failOpen。
