The last feature is child delegation: isolated child Threads by default, with explicit reuse supported. Frozen target/input, child admission, parent/child mapping and both schedules commit in one Session transaction. Retries/replacement hosts do not resolve another target or admit another task. Cancellation before admission persists a tombstone without starting work; later cancellation targets only the mapped child Turn, while parent pause does not pause the child. Bounded ready-index reads order new Turns by storage admission time, preventing newly created Threads in one Session from overtaking older waiting work in another. This does not promise tenant quotas or strict round-robin latency. Pause, backoff, leases and version selection retain their existing contract.

- SessionSpec/View, ThreadBinding/Spec/View and DurableThread are connected. Session creation atomically creates the primary Thread. Each Thread owns its FIFO, lease, epoch, checkpoint, journal, resources and invocation records. Runtime active/claim/ready scheduling uses Thread identity; different Threads in one Session can run concurrently without another storage SPI.
- Native state, journals and AgentScope RuntimeContext use full Thread identity; DurableTurn represents the task and Backend persists separate Run/Step records. Idempotent preparation, lost-owner takeover and checkpoint/event commits retain the original transaction boundary.
- Session owns lifecycle, metadata, the Thread directory, public event sequence and requestId deduplication. Thread create/get/list/close APIs are connected; submission/control digests include the target Thread, rejecting foreign task access and request identity reuse.
- HTTP Backend, public HTTP, Hands ExecutionRequest, Sandbox/MCP/Worker callers and all existing Java examples use Thread identity. SessionDefinition and RunExecutor are removed; DelegationExecutor creates a stable child Thread in the same Session. Reuse, parent provenance and cancellation policy remain incomplete.
- Thread-scoped checkpoint restore/fork copies native state and private resources; the target Session must already exist. Closed Sessions/Threads reject new restoration, while retries can recover an existing receipt.
- Core persists cumulative reasoning position with native checkpoints, including progress changes without context changes. Another invocation of the same Turn resumes that position; a new Turn starts at zero. Tool continuation consumes no additional reasoning iteration.
- External-result application records an ACTING Step before subsequent reasoning, including returnDirect paths without another model call. Reasoning and finalization recovery create Steps in the new Run and may reference an interrupted Step. Ordinary finalization advances the current Step's phase.
- Native facts carry Step association; the adapter maps associated interactions and completed messages to the same Run/Step. Model replay uses committed outcomes without inventing another actual provider request.
- Tool projections retain Run/Step fields and match the snapshot schema. The format at that stage was `agentscope-thread-log-v1` (directly replaced by journal-v2 below), without old-format readers or converters.
